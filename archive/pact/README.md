# PACT

**Project Architecture & Collaboration Toolkit — 项目架构与协作工具包。**

PACT 帮助新项目建立共同约定，帮助老项目在保留有效设计的基础上接入同一套协作方式。
不同成员和 agent 应能找到同一份有效规格，保持模块边界，交付可验证且有终点的结果。
PACT 同时作为文档控制台：通过现有项目入口和当前功能规格，呈现交付目标、真实验收
入口、候选与环境证据、剩余工作，并将后续职责交给 VERIFY、OPAID 或 CICD。

## 当前交付形态

本子项目提供 [PACT skill](skills/pact/SKILL.md)、[共享文档规范](skills/pact/references/document-protocol.md)、按需接入参考，以及 AGENTS 和
功能验收模板。它可以由具备文件读写与命令能力的 agent 执行；控制台以文档形式交付，目前没有 CLI、自动
安装器、运行服务或插件发布包。具体范围与验收见 [SPEC.md](SPEC.md)。

安装时将完整 `skills/pact/` 放入宿主支持的项目技能目录；支持共同布局时使用
`.agents/skills/pact/`。所需引用均在该 skill 内部。VERIFY、OPAID 与 CICD 使用仓库
根目录各自的唯一源码，不在本子项目中复制维护。四者分工见 [仓库入口](../README.md)。

## 使用例子

- “使用 PACT 为这个新项目建立最小规范，首轮只交付已约定的用户路径。”
- “使用 PACT 只读检查这个老项目的有效规格、agent 入口与检查缺口。”
- “使用 PACT 接入现有项目，复用原有 SPEC、ADR 和验收文档。”
- “使用 PACT 评估这次公共接口变化，依据现有授权更新相关约定。”
- “使用 PACT 查看当前功能的交付状态，告诉我从哪里验收、还有哪些结果尚未验证。”

诊断请求保持只读；接入或修改请求在已授权范围内生成并实施可审阅变更。
验收设计与环境业务验证使用 VERIFY，常规实现和单元测试使用 OPAID，版本交付使用
CICD。各 skill 共用有效文档与场景标识，无需每次切换重新建立规格或要求确认。
